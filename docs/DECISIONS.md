| ID | 決定 |

## 2. 未指定の細部を補う実装案

以下はユーザーが確定した値ではない。計画書PRのレビューまたは各工程の受入時に採用を記録する。特に公開競技の条件を、未確定のまま実装者の判断で固定しない。

| ID | 実装案 | 決める時点・扱い |
|---|---|---|
| D01 | サイコロは1個、目標の達成順は自由。 | P1〜P2の設計確認。ユーザーの完走形式を最小構成で具体化する案。 |
| D02 | 配置案Aの10座標、サイコロ中央、キャラクター隣接マス。 | P2前に画像と座標で確認する。位置が固定という要件は確定済みだが、座標自体は未指定。 |
| D03 | 開始姿勢は元の基本姿勢、各目標は独立・等確率の1〜6。 | P2前。サイコロの面配置は変えず、開始姿勢と生成方法を固定する。 |
| D04 | 0.01秒未満は切り捨て、同じ0.01秒は同記録。 | P2前。0.01秒単位は指定済みで、丸め方のみが案。 |
| D05 | 目標出現後に中断したプレイは参考記録とし、通常ベストとランキングへ入れない。 | P3と公開前。途中再開の可否と文言も一緒に決める。 |
| D06 | 元のタッチ向け・標準の速度は変えず、記録に操作設定IDを付ける。 | P1では継承を優先。ランキングを分けるなどの正式な比較条件はP4前に決める。 |
| D07 | 通常の再挑戦では固定座標を維持し、新しい目を生成する。 | P3前。同じ問題を選んで再挑戦する別機能は初回に追加しない。 |
| D08 | 低い秒数ほど上位のオンライン記録を別ゲームIDで扱う。 | P4前に既存接続契約を調査する。実装・公開は別許可。 |

D02〜D04が未確定の間でも、P1の流用確認は進められる。D05〜D08の未確定を理由に盤面・操作の流用まで停止する必要はないが、正式な記録受付は開始しない。

## 3. 前の提案から採用しない内容

| 前の提案 | 今回の扱い |
|---|---|
| 目標の位置まで毎回ランダムにする。 | 採用しない。10か所の位置は固定する。 |
| キャラクターを小さくする、位置関係を変える、非表示にする。 | 採用しない。元のキャラクターをそのまま使う。 |
| 端末の転がる時間を直ちに統一する。 | 採用しない。操作継承を優先し、競技の比較条件を別途決める。 |
| 日替わり共通問題を基本モードにする。 | 採用しない。ユーザーが指定したランダムな目の形式を維持する。 |
| ゲーム開始ボタン、3カウント、最初の移動で計測を始める。 | 採用しない。完全露出の確定だけを開始条件にする。 |
| クオンパの特殊パネルや対戦を追加する。 | 初回対象外。参考作品の仕様を自動採用しない。 |

## 4. 運用上の制限

今回許可された作業は計画書と調査資料の作成・保存である。ゲームコードの実装や本番変更を始めない。文書の保存先は作業ブランチで、Draft PRまで提出する。

`main`へ直接pushしない。マージ、自動マージ、Ready化、保護の緩和、強制push、本番データベース変更、公開先の変更、実験場への登録は行わない。元の `sainome` を変更しない。
