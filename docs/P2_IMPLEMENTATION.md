## 対象

現行計画書 v1.1 のP2を、P1が反映された `main@4fa200b7e6b7aa2fa303dcb093e13f46a752fd85` から実装した。元の `sainome`、本番データベース、公開設定は変更していない。

P2の範囲は、固定10か所の目標、目の一括生成、埋まったサイコロの上昇、完全露出を起点とする計測、上面一致による達成、0.01秒単位の暫定表示である。結果画面、再挑戦、自己ベスト、保存、共有、ランキング、正式な中断記録はP3以降の対象である。

## 未確定事項を明示した暫定設定

計画書のD02〜D04は未確定のため、正式な競技条件としては扱わない。P2のローカル検証用に、次の版付き設定を使う。

| 項目 | 暫定値 |
|---|---|
| ルール版 | `p2-target-time-provisional-v1` |
| 配置版 | `layout-a-provisional-v1` |
| 座標 | `(1,1), (1,3), (1,5), (2,2), (2,4), (4,2), (4,4), (5,1), (5,3), (5,5)` |
| 生成版 | `independent-uniform-v1` |
| 生成方法 | 各目標を独立に1〜6へ変換し、10個を一括確定。引き直しなし |
| 端数 | `floor(elapsedMs / 10)`で0.01秒未満を切捨て |

配置、開始姿勢、生成方法、端数処理が正式決定されるまで、P2の表示値を自己ベストやランキングへ保存しない。

## 実装した状態と判定

- `WAITING_FOR_CLIMB` / `CLIMBING`: P1の盤面・操作を継承し、目標と時計を開始しない。
- `RISING`: 登り完了後に10目標を一括生成・表示し、サイコロを上昇させる。時計は0.00秒のまま、転がし判定は受け付けない。
- `RUNNING`: 上昇の進行度が1に達し、サイコロを通常状態・最終位置へ確定したイベントで時計を開始する。移動完了後に座標と上面を確定してから目標を判定する。
- `FINISHED`: 10個目の未達成目標が一致した移動完了時に終了時刻とスコアを確定し、以後の入力・判定・時計更新を完走処理へ反映しない。

目標達成はID集合で管理し、同じ目標の再訪では達成数を増やさない。下面・側面・キャラクターの接触・移動途中の見かけの面では達成しない。

## 主な変更箇所

- `js/saisupi-config.js`: 版付きの配置案Aと目標数を定義。
- `js/saisupi-targets.js`: 座標検証、一括乱数生成、座標検索を描画非依存で実装。
- `js/saisupi-clock.js`: 注入可能な時計、ミリ秒差分、0.01秒整数化、表示を実装。
- `js/saisupi-session.js`: 上昇・計測中・完走の状態、目標IDの重複防止、時刻の一度だけの確定を実装。
- `js/webgl-game.js`: 目標マーカー、上昇完了と時計、移動完了後の上面一致をP1の流用層へ接続。
- `index.html` / `css/style.css` / `js/main.js`: 経過時間と達成数のHUDを追加。

生成・時計・状態管理は注入可能な乱数・時刻で自動検査できるようにし、描画資源の準備失敗時は計測を開始せず初期待機へ戻す。
