# サイスピの独立レビュー

[共通の許可範囲と制限](../../../AGENTS.md)を適用する。本スキルは別担当の審査に限る。新しい権限やゲーム仕様を追加しない。

## 対象を固定する

依頼範囲、基準コミット、審査コミット、差分、実装担当の検査証拠を取得する。取得できる情報はリポジトリから確認し、ないものを推定で補わない。対象が更新された場合は、どの版を審査したかを分ける。

実装担当と別の担当または独立したエージェント実行であることを記録する。独立性を確保できない場合は「自己検査のみ・独立レビュー未実施」とし、独立レビューの合格を出さない。

## 変更に合わせて確認する

仕様を確認するときは[現行計画](../../../docs/IMPLEMENTATION_PLAN.md)、採用状況を確認するときは[決定事項](../../../docs/DECISIONS.md)、必要な検査は[受入検査](../../../docs/ACCEPTANCE_TESTS.md)の該当範囲を読む。全調査資料を一括で読み込む必要はない。

ゲームの変更では、影響する仕様と失敗条件を独立に確認する。AI指示の変更では、許可範囲、必須検査、仕様と方法の区別、参照切れ、過剰な読込や早期停止、証拠のない実機合格を重点的に確認する。確認方法や確認順は固定しない。

審査中は対象ブランチを修正しない。問題は重要度、対象ファイル・位置、再現条件または根拠、期待される状態を添えて実装担当へ返す。修正は実装担当が行い、修正後の版を改めて審査する。

## 結果を残す

実施者・実行主体、基準版、審査版、確認範囲、実行環境、検査結果、指摘、未確認事項を記録する。指摘がない場合も、確認範囲と限界を省かない。依頼外の変更提案は必須修正と分ける。

レビューを終えたことと、ゲームの実機受入・公開・統合を許可することは別である。結論は「指摘あり」「確認範囲で重大な指摘なし」「検証不能」等で明示し、実施していない検査を埋めない。
